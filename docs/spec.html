VAU 1: the unit standard

Version 1, November 2026. This document says what a Vector Abliteration Unit is and what a host must do to run one. The package in src/vau/ implements the host's side; src/vau/units/ holds the built-in units.

1. Units and hosts

A unit is one Python file that changes, or reads, what a model does from inside while it runs. A host is the application that loads the model, finds units, checks them, and runs the ones a user puts in a chain. The two meet only through a small interface:

  • the unit declares itself in a manifest and supplies a few functions;
  • the host supplies a UnitContext, through which the unit reads its parameters and asks for places in the model to act on.

A unit never registers a hook on the model itself. It asks the host, and the host registers the hook, may wrap it (to measure how much it changes what it touches, for instance), and removes it after the run.

2. The manifest

A unit file defines a module-level dict UNIT:

Every unit has two names, a full one and a short one, and the catalogue gives both (title, short). A host chooses which to show where: the short one in a strip's top bar, say, and the full one in its help and its lists. Either is shown with the unit's collection's prefix (vComponent Clamp, vClamp; section 5d).

3. Parameters

Each entry in params has a key (lower case, and not one of the target names head, attn, mlp, block, layer, which a line uses for its target), a label, a tip, and a kind. The tip is what a host shows when the pointer rests on the control: one short line (at most 100 characters), written as a formula or as code where the transformation can be shown that way, for example h' = (1 − mix)·h + mix · L·tanh(h / L) for the vTanh Squash's mix. The host features have tips too.

KindTakes
knob, faderA number, with min, max, default and optionally step. A unit has at most one fader, its main control.
intA whole number, with min, max, default.
choiceOne of choices.
toggle0 or 1.
directionThe name of a direction the host keeps.
textFree text, with an optional hint.

when makes a parameter apply only in some settings. For example, {"shape": ["linear", "bell"]} applies while the parameter shape has one of those values (Abliterate's peak, width and edge mean nothing while its shape is flat), and {"host": ["sink"]} applies only where the host says its model has that property (section 4). When a parameter does not apply for now, a host dims it, and when its host flag is one the model lacks, the host leaves it out; the card runtime does both (section 5f). The host features use when too, so that the envelope's peak, width and edge apply while the envelope is not none, and the control seed while the control is random.

required: true marks a parameter the line must give. neutral is the value at which the unit changes nothing, where it has one. A unit set to all its neutral values must leave the model's output exactly as it is without the unit, and hosts and the conformance checks test that.

In a chain a line is written id target=value key=value ..., as in delay layer=6 time=4 feedback=0.3 mix=0.5. Values reach the unit as strings; UnitContext turns them into numbers with the manifest's defaults.

4. Sites, capabilities and adapters

Units name a site, a kind of place in a model, not a particular model:

CapabilityWhat the host offers
streamA sequence of vectors that runs through the stack, one per position: a language model's residual stream, or the hidden states of a diffusion transformer.
outputWhat one component (attention, MLP) writes.
weightsA component's parameters, changed for a run and restored after.
logitsThe output distribution at each step.
orderedPositions in order, so that a position can draw on earlier ones.
statsEach layer's mean, per-dimension spread and mean size over a reference set, measured on the unchanged model.
pcaEach layer's principal directions over a reference set.
directionsNamed directions, one vector per layer.
textsThe unchanged model run on given inputs, to measure or fit before a run, and the host's reference set of ordinary inputs.
contrastsThe two sets of texts a direction was made from (an empty second set means the first was set against the reference set).

A unit needs its site, ordered if its axis is ordered, directions if it has a direction parameter, and whatever it lists in requires. A host says what it offers in Host.capabilities(). A unit whose needs the host cannot meet is listed as unavailable, with what it lacks, and is not run.

A host reaches a model through an adapter, which maps the sites onto one architecture. The package's adapter covers GPT-2, Pythia and Llama-style language models. A unit that keeps to its site and its UnitContext runs unchanged under a later adapter (for a diffusion model, or an audio model) that offers the same capabilities.

Position 0 and the attention sink

Most language models keep an attention sink at the first position, that is, a token every head can attend to, which carries very large values. Several units leave it alone (in the Core Collection, Lookback, Running Average, Position Repeat and Quantise), while two of them, Sparsify and Component Clamp, offer to bend it anyway with sink too. Other models have no sink there, and in an audio model the first position is simply the first frame. A host says which with Host.sink() (true by default, as for a language model), and a unit reads it as u.sink; where it is false, the units bend the first position like any other, and sink too is left out (when: {"host": ["sink"]}).

Site and space

site says where a host attaches a unit's hook, and it is what capabilities are matched against; space says what the unit transforms. Mostly the two agree, so that a stream unit transforms the stream, an output unit what a component writes (component), and a logits unit the next-token distribution. Where they differ, the manifest says so. vNeuron, for example, hooks the MLP's output but changes single neurons, so its space is hidden. A host may use the space to group its units, or to offer only those whose space its model has (a music model's conditioning, say), and heads, attention patterns and further spaces are added as hosts expose them.

Some units act on each coordinate of the stream separately (the Core Collection's vTanh Squash, vQuantise, vSparsify and vComponent Clamp). The stream's coordinates have a weaker claim to meaning than an MLP's neurons, which its nonlinearity singles out, and how much weaker depends on the model's norms. Such a unit says so in its help; the standard has no field for it.

5. Functions

All take a UnitContext, called u by convention.

FunctionWhenDoes
validate(u)optional, when a line is read, before any model is loadedRaises u.error("...") for a line that cannot work. The host has already checked required parameters, choices, numbers and targets.
prepare(u)optional, before any hook goes onMeasures or fits on the unchanged model (u.stats(), u.pca(layer), the host's capture), so that what it measures is of the model as it was.
edit(u, layer)for a stream unitReturns an edit fn(h, pos) -> h for one place in the stream. h is (batch, positions, width); pos gives each position's index along the axis. It must return a tensor of the same shape and dtype.
attach(u)for any other unit, or a stream unit that needs moreAsks the host for hooks: u.hook_stream(make), u.hook_output(module, fn), u.hook_input(module, fn), u.on_restore(fn).
read(u, data)for a meterReturns one reading per step (section 5b).
code(u)optional{"expr": ..., "note": ..., "uses": [functions]} for a host's view of the code that runs: an expression for the edit, a note, and the functions whose source to print.

UnitContext gives:

  • parameters: u.num(key), u.int(key), u.str(key), u.flag(key), u.clamped(key), u.params;
  • the strip: u.lineno and u.error(msg);
  • the host: u.device, u.stats(), u.pca(layer), u.pca_scales(layer) (the spread along each principal direction), u.direction(key), u.layers() (places in the stream), u.blocks() (blocks, from 0), u.depth() (how many blocks the model has), u.component(kind, block) (a block's attn or mlp output projection), u.memory(layer) (a store that lasts one run), u.direction_texts(key), u.reference_texts(), u.capture(texts, modules) (each module's inputs and outputs on the unchanged model), u.cache(kind, key) (a file the host keeps for the loaded model), and the hook requests above.

5a. Host features

Every strip also takes the host features, which the host applies around the unit's own edit, so that no unit implements them (vau.hostfx). Their keys are reserved: a unit may not take a parameter of the same name.

KeyKindDoes
wetknob, 0 to 1, default 1How much of the strip's change is applied. 0 is neutral.
envnone, linear, bell, flatAn envelope over the depth: the change is scaled at each layer (a stream unit) or block (a unit that names the block it hooks).
epeak, ewidth, eedgeknobs, shares of the depthWhere the envelope peaks, how far it reaches either side, and its value at that reach as a share of the peak.
keepnormtoggleAfter the change, each position is scaled back to the size it had before it. A unit that only changes sizes (the vNorm Shrink) is undone by it.
wfrom, wtoints, default 0A window: the strip acts only from step wfrom to step wto (step 1 is the pass that writes the first new token; earlier positions are the prompt's; wto 0 is to the end). Both 0 is everywhere. The host supplies positions(n, device) and prompt_length().
controlnone, randomEvery direction the strip uses is replaced, at each layer, by a random direction of the same size, drawn from cseed, the direction's name and the layer. A unit fitted to a direction's texts (vMorph) refuses it.
cseedintThe control's seed.

A unit that hooks a component's output passes the block to u.hook_output(module, fn, block=...) so that the envelope can apply; without it only wet and keepnorm do.

5b. Meters

A meter reads the model and changes nothing: category: meter, level: probe, site: stream (it reads the stream at one place) or site: logits (it reads the model's next-token distribution). It declares how its readings are drawn:

"display": {"kind": "series", "label": "uncertainty about the next token", "unit": "bits"}
DisplayEach readingDrawn as
series{"value": number}the value at the shown step, for each text, and a line over every step
words{"top": [[text, number], ...]}a ranked list at the shown step, like a logit lens

The meter supplies read(u, data). The host fills a meter after the run, in a teacher-forced pass over each text (the original text with the meters alone, the diverged text with the whole chain), and hands it, one row per step (step j is the pass that wrote token j):

KeyHolds
stream(steps, width): the stream at the meter's place, for a stream meter
logprobs(steps, vocabulary): the next-token log probabilities as the chain leaves the model, for a logits meter
tokensthe ids written
decodea function from a list of ids to text

read returns one reading per step; vau.read checks the count and the keys. A meter registers no hook while the texts are written.

5c. Explainers (optional)

A unit may come with an explainer: an animated figure of what its code computes, which a host shows as the unit's help and the site shows on the units page. It is a script beside the unit's file, named like it with .explain.js in place of .py (compressor.py, compressor.explain.js). It registers itself with the explainer runtime that the vau package ships (vau/explain/explain.js):

(function (X) {
  if (!X) return;
  var H = X.h;                                  // drawing helpers: H.T (text), H.R (rect), H.L (line), H.stage, ...
  X.register("gain", {
    caption: "What the figure shows, in a sentence or two.",
    examples: "k 0.5 and 2",                   // the settings examples.json has texts for, if any
    still: 1500,                                // the moment drawn once under reduced motion (ms)
    draw: function (t, ex) {                    // t: the figure's clock, ms; ex: the example texts or null
      return { svg: H.T(20, 30, "k = 2"), read: "h' = k · h", setting: 0 };
    },
  });
})(window.VAUExplain);

draw returns the inside of a 400 × 210 SVG, the readout line under it, and which of the unit's example settings it is showing (setting, an index into the unit's rows in examples.json; a meter also gives the token it has reached). Its marks take the runtime's classes (f-acc, s-line, t-s and so on), so that they follow the host's colours. The runtime, for its part, adds the pause button, stops a figure while it is off screen, and draws it once, at the moment still gives, when the reader prefers reduced motion.

A host serves the files vau.explain_files(registry) names and no others: the runtime (explain.js, explain.css), the example texts (examples.json) and each unit's explainer as <id>.explain.js. It loads the runtime, then the explainers it needs, and calls VAUExplain.mount(element, id, {examples: url}). The catalogue marks each unit that has an explainer (explain: true). A host without one shows the manifest alone; the manifest checks do not ask for an explainer.

5d. Collections and their look (host presentation)

A collection is a set of units published together, with a name and, if it has one, a look. The look is the stylesheet a host draws the units' strips with, so that on any desk they read as that collection's, apart from the host's own strips. The units the vau package ships are the Core Collection (id core). A unit's catalogue entry names its collection (collection: "core"), or null for a unit outside any collection, such as one in a user's folder, and vau.COLLECTIONS lists the collections with their titles, looks and prefixes. A collection may give a prefix for its units' names, which a host shows before the name wherever it names a unit in that collection: on its strip's top line, in menus and lists, and in help. The Core Collection's prefix is a small lowercase v (vNorm Shrink, vSparsify), which marks its units as vector effects, apart from any audio effects a host may also have; the catalogue gives it as prefix ("" for a unit outside any collection). The manifest's title and the unit's id do not change, so chains and saved recipes keep working. More collections can come later, each with a look of its own.

A unit's strip is shared between the host and VAU:

  • The host draws the strip's frame and its top line: the power light, the strip's number, the unit's name, the help button and the output summary (for example an activity light). These keep the host's look on every strip.
  • VAU supplies what goes in them, that is, the help text and graphics (the manifest's help and tips, and the explainer, section 5c), and the suggested output for the summary (a meter's display, section 5b, or an effect's summary, section 5e). It also supplies the card, which holds the unit's controls (target, knobs, menus, toggles, fader) or a meter's screen, drawn in the look of the unit's collection.

A host that draws units as strips SHOULD let VAU draw each unit's card:

  • it gives VAU an element for the card, which fills the strip below the top line, to the strip's left, right and bottom edges, and calls VAUCard.mount(element, options) from the card runtime (section 5f). VAU gives the host that whole space and draws everything on it: the unit's controls, its target, the host features, a meter's screen where the host supplies one, and the footer;
  • it loads the runtime and each collection's interface, which vau.look_files() names (card.js, card.css, core.css, core.json), and serves those files and no others for it;
  • the strip's frame and top line stay outside the card, in the host's own look.

A host may draw a card itself, from the same manifest and interface, but the standard discourages it, since a unit should look and handle the same on every host. A host may also give a unit a display title of its own where the canonical one would mislead in its setting; an audio host, for example, may call vPosition Repeat "Frame Repeat", since its positions are 40 ms frames of sound. The unit's id, its parameter keys and its canonical title do not change, and the host shows the canonical title, with its collection's prefix, in the unit's help (the prefix goes with the canonical name only). Units outside any collection get a plain card from the same runtime.

A collection's look is an interface language of its own, kept apart from its units. A unit's manifest says what the unit does, its parameters and the readings it suggests, and nothing about how it looks. The interface is two files in vau/look/: a stylesheet (core.css), and the rest (core.json), which says which component draws each control (section 5f) and gives the units' tint (#rrggbb), either one for the whole collection (tint) or, where a collection wants it, one per unit (tints, by id). The Core Collection's units share one tint, the blue of the faceplate, and the catalogue entry carries it as tint (null outside a collection). A host may let the tint into its own frame or top line (a glass top bar, say), while the card keeps its collection's look. Another collection can bring a different interface for the same kinds of unit. The interface may also group the collection's units by what they act on (groups: an id, a title, a sentence, and the units), for a host's menus and lists. In the Core Collection these groups are along time (Lookback, Running Average, Position Repeat), on the stream's size (Norm Shrink), coordinate by coordinate (Tanh Squash, Quantise, Sparsify, Component Clamp), along directions and principal bands (Principal Bands, Band Shrink, Rotate), inside a block (Abliterate, Morph, Neuron), and the meters.

A collection's stylesheet sets only the --vu-* properties on its class, and styles the mark; the shapes of the components belong to the runtime (card.css), and the top line and the frame stay the host's.

5e. The summary a unit suggests

A host shows a summary of each strip after a run: for example, how much the strip changed what it touched at each step. A unit that changes the model may suggest what that summary reads, with an optional summary in its manifest:

"summary": {"reads": "gain", "label": "gain reduction"}

reads is one of four measures, which a host computes from what each of the unit's hooks received and returned, at each position, and averages over the unit's hooks:

readsThe measureShown in
changethe size of the change over the size of what it touched, ‖h′ − h‖ / ‖h‖per cent
gainthe change in size, 20 log₁₀(‖h′‖ / ‖h‖)dB
turnthe angle between what it touched and what it left, arccos of their cosinedegrees
touchedthe share of components it changedper cent

label says what the reading is for this unit (gain reduction, rotation, zeroed). A host shows the label and the reading at the shown step, and may draw the reading over the steps. A meter suggests its own readings through its display (section 5b) and has no summary. A host that cannot compute a measure shows its own summary.

5f. The interface language: components

A collection's interface draws a unit's card from a fixed vocabulary of components, which the card runtime (vau/look/card.js) implements once for every collection. The collection chooses which component draws each control, and styles them all. A unit names none of them, which means that a later collection can draw the same units with other components, or in another look.

A collection's interface file (look/<collection>.json) maps controls onto components:

"components": {
  "defaults": {"knob": "knob-1", "fader": "knob-big-1", "choice": "selector", "toggle": "light-1",
               "target": "knob-small-1", "target-menu": "menu-1", "host-knob": "knob-small-1"},
  "units": {"gate": {"keep": "knob-big-3"}}
}

defaults maps a parameter's kind, or a control's role (target, target-menu, host-knob, host-choice, host-toggle), to a component, and units maps a unit's own keys. Here, selector picks selector-small or selector-med by the number of choices, and a menu where there are more than five, or where the settings' names would not fit around the lever (one longer than 8 characters, or more than 15 in all). A direction is always its own kind, and by default a menu, since its choices are the host's directions. The Core Collection draws its main parameter as a large knob, which is why its cards have no faders.

VAUCard.mount(element, options) takes the unit's catalogue entry, its collection's interface, get(key) and set(key, value) for the line, the host's directions, and the controls only the host can describe: the target (the model's layers and heads) and the host features, each as {key, label, kind, role, min, max, choices, reset, get(), put(value)}. A meter's screen is the host's, since it holds the run's readings; the host draws a one-number reading on it with VAUCard.needle(original, diverged, unit) (meter-1) where the look shows needles (--vu-meter-needle), and passes it as screen, which the card puts in its main place. It also takes the host's flags (flags, such as {"sink": false} for a model with no attention sink), by which the card leaves out controls (section 3), and the unit's presets on the host's model (presets, start, from the catalogue; section 5g) with onPreset(preset): the card lists them in a menu at its head, and hands the one chosen to the host, which writes its line. A control whose when does not hold is dimmed, and comes back as soon as the control it depends on is turned.

5g. Presets, by model

A setting that bends one model well can silence another: on a music model, Lookback at its default mix of 0.5 leaves the output almost silent, and several units do nothing audible at their defaults. So VAU keeps presets per model, not per unit: one file for each model they were measured on, in vau/presets/.

A preset file gives:

  • model: the model's name, the ids a host may know it by, and its kind (text, music);
  • measured: who measured the presets, when, how, and what each figure means;
  • units: for each unit, its presets and start, the preset a host should begin the unit at on this model (or none, where the manifest's default does).

A preset is a chain line with a name and a tip, together with the figures it was kept on: {"name": "Ghost Trail", "line": "delay layer=6 time=4 feedback=0.3 mix=0.2 keepnorm=1", "tip": "...", "held_out": {...}}. Its line may set the target, the unit's parameters and the host features. A preset is kept only if it does what its tip says on inputs it was not chosen on. The first set, for example, 75 presets for 12 units on Magenta RT 2 small, was searched on six seeds and kept only if it broke the sound on none of ten others, and the measures that moved beyond chance are named (heard).

vau.presets_for(model) finds a model's presets by any of its ids or its name. A host that passes its model to Registry.catalogue(capabilities, model=...) gets each unit's presets and start in its catalogue entry, and presets at the top says which model and how they were measured. Hosts may keep presets of their own and the user's beside these.

5h. The Audio Collection, and MLX versions

VAU comes in two versions. VAU text is the Core Collection on language models, as the units are written. VAU audio is the Audio Collection, that is, the Core Collection's units tuned for an audio model; the files and the edits are the same, with the names, defaults, ranges and placements that were found to work on one (Magenta RT 2 small, where a position is a 40 ms frame and the first position holds no attention sink).

A collection may be made from another. Its entry in vau.COLLECTIONS then names the collection it comes from, and its tuning, a file (vau/collections/audio.json) that says, for each unit it keeps, what differs from the Core manifest. A unit not listed is not in the collection; the Audio Collection, for example, leaves out the meters and Morph, which need a host to offer logits or texts. A host chooses the collection with Registry(collection="audio"), and each unit then carries a manifest derived from the Core one (the Core one is not changed), with collection.of(unit) giving "audio". A tuning entry may give:

  • title and short: the unit's names here. The Audio Collection has no prefix, and calls Position Repeat Frame Repeat, since its positions are frames;
  • params: for each setting, what differs: default, max, tip, hidden (the setting has no effect on the model), safe (the part of its range in which the sound neither fell silent nor overdrove on the seeds measured, with measured: true, and fragile where no part held), and taper (how the knob's travel maps onto a range opened past the Core's, as pairs of travel and value: Abliterate's Strength runs to 6 here);
  • host_defaults: the host features (5a) the unit starts with, such as Keep size on Lookback and Running Average, which fell near silent without it. A line's own setting wins; hostfx.settings reads them;
  • places and place_default: the layers or blocks it was measured to work at, and where it starts ("all" for every block);
  • note: what the unit does differently here, beside its help.

The catalogue of a derived collection says so at the top (collection, and model, the model it was tuned on, with sink), and it carries that model's presets (5g) without the host having to name it. The Audio Collection shares the Core's stylesheet, with an interface of its own (look/audio.json, its tint and groups). The tuning is written by tools/import_audio.py from the audio host it was measured in, and it keeps only what differs from the Core manifests, so that a change to a Core unit reaches both versions.

MLX versions (optional). vau.mlx holds MLX versions of three units' edits (Neuron, Quantise and Abliterate), for a host whose model runs in MLX on Apple silicon, so that the edit stays on the GPU instead of copying the stream to torch and back at each hooked layer. It needs mlx (pip install "vau[mlx]"), imported only when an edit is first made. Each edit is marked fn.mlx = True; vau.mlx.port() swaps a strip's torch hooks for them in a host that keeps its hooks in tables ({"edits": {layer: [fn]}, "outs": {(block, kind): [fn]}, "ins": {(block, kind): [fn]}}), and keeps the torch path where a host feature needs it (a window, a random control). tests/test_mlx.py checks each against its unit, where MLX is installed.

6. Where units come from

A host loads the built-in units from the package (vau.BUILTIN), then any folders it adds, such as a user folder. A unit is ordinary Python, so loading one runs it:

  • a host loads units only from local folders;
  • it never downloads one;
  • it marks every unit that is not built in, so the user can see which code is whose.

A file that fails to load, fails the checks, or takes an id already in use is left out and listed with its reason. The other units are unaffected.

7. Conformance

vau.testing.conformance(unit) checks a unit without a model, on a stand-in host with random statistics and directions:

  • its manifest;
  • its example line;
  • that its edit keeps the stream's shape and dtype;
  • that its neutral values change nothing.

A host should also test neutrality on a real model, where the output must be identical.

8. Versions

This is VAU 1. A host refuses a unit written for a version it does not run. Within VAU 1, additions keep existing units working; anything that would break them waits for VAU 2.
